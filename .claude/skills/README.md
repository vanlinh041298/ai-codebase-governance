# Repository Skills

These workspace skills cover the main change workflow:

`grill-with-docs → to-spec → to-tickets → implement → code-review → retro`

- `grill-with-docs`: resolve an unsettled plan and document durable terms/decisions.
- `to-spec`: record settled decisions for work spanning sessions.
- `to-tickets`: split an approved plan into dependency-aware, verifiable slices.
- `implement`: build one approved slice, validate it, review it, and commit on a feature branch.
- `code-review`: review standards compliance and spec fulfillment separately.
- `retro`: propose environment improvements based on concrete session evidence.

The spec and ticket skills require an agreed source and a configured publishing destination before they publish anything. `to-spec`, `to-tickets`, `implement`, and `retro` are user-invoked; `code-review` may also be suggested for review requests.
