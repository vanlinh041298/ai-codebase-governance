# Contributing

Keep this project portable across repositories, teams, and AI tools.

1. Open an issue describing the supported workflow and affected provider or language.
2. Work in a feature branch or isolated Git worktree.
3. Avoid machine-specific paths, usernames, credentials, generated reports, or local source links.
4. Keep workflows secure by default with least-privilege permissions and fail-closed checks.
5. Make templates easy to opt into; do not assume a package manager, cloud provider, or deployment platform.
6. Update the guide, README, runbook, and related agent skill when behavior changes.
7. Run relevant validation and include results in the pull request.

Do not commit secrets or private organization details. Pull requests are expected to preserve `main` and `develop` protections.
